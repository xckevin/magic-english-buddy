## AI 资源：已落地的方式

使用开源 [Kokoro](https://github.com/hexgrad/kokoro) 和 [Kokoro-82M 模型](https://huggingface.co/hexgrad/Kokoro-82M) 在开发机预生成 MP3。模型权重不进入前端，也不上传儿童录音。音频元数据位于 `src/data/audio/manifest.json`，文件位于 `public/audio/`。词语时间点来自模型预测时长，未使用旧故事数据里手写的假时间轴。

本次生成 295 个音频文件，共 3,643,700 字节（约 3.64 MB），覆盖 L1 的 20 篇故事、英文听题和 190 个单词。模型版本、音色和校验值见 `public/audio/README.md`。生产 PWA 整体预缓存约 7.25 MiB，音频增加了首次安装下载量。

模型较小、提供英语语音和词时间点，适合这个固定课程场景。也核查了 [kokoro-onnx](https://github.com/thewh1teagle/kokoro-onnx) 的量化模型方案；本次采用官方 Python 管线以直接获得对齐信息。运行时下载完整 AI 模型会增加低端设备的首次等待与内存需求，因此这里使用预生成文件。

```sh
# 默认导出 L1；也可指定 2–7，为后续课程生成资源
node scripts/export-audio-input.mjs 1
uv run --python 3.13 scripts/generate-audio.py
node scripts/verify-audio.mjs

# 审计所有课文的可查词覆盖，输出缺词及涉及的课程
node scripts/audit-content.mjs
```

生成工具要求 uv、Python 和 ffmpeg。首次运行下载依赖和模型；相同文本与配置复用已生成资源。生成内容已做文件可解码、时长、词时间点和浏览器播放验证；尚未逐句由英语教师听校，尤其拟声词、人名和拼字读法值得人工试听。

## 浏览器依据

- [MDN：SpeechSynthesis.cancel](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/cancel)：取消影响整个语音队列，应用需隔离调用方状态。
- [MDN：boundary 事件](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisUtterance/boundary_event)：不能假定所有设备都提供词边界回调。
- [Vite PWA：precache](https://vite-pwa-org.netlify.app/guide/service-worker-precache)：音频必须明确加入缓存清单，单纯访问过页面不足以保证离线听课。
- [Workbox：缓存音视频](https://developer.chrome.com/docs/workbox/serving-cached-audio-and-video)：媒体 Range 请求需要额外处理。本实现完整 fetch 缓存文件后交给 Web Audio 解码，避免 HTMLAudio 的分段请求与 precache 冲突。

## 验收命令与边界

最终校验：209 项单元测试全部通过；TypeScript 检查与生产构建通过；ESLint 为 0 错误、27 条警告（主要是 console 和旧代码规则提示）。构建仍提示一个约 695 kB 的课程数据 chunk 较大，本轮未扩大到按级别拆包。

```sh

```

`test:e2e` 基于生产构建运行当前的功能回归和 UX 回归。录音自动化使用 Chromium 假麦克风输入，编码和回放是浏览器真实 API；不能替代 Android/iPhone 真机对系统权限弹窗和扬声器音质的验证。

浏览器回归结果：14 项通过，1 项跳过（WebKit 无 Chromium 假麦克风）。Chrome 验证了 PWA 缓存后断网重载、查词、答题和预生成音频；WebKit 验证了在线条件下禁用系统 TTS 的音频解码、暂停/恢复和跟读。WebKit 的断网重载测试遇到浏览器内部错误，未计入已验证能力；上游有相关 [Playwright WebKit 重载问题](https://github.com/microsoft/playwright/issues/42273)，但尚不能证明是同一原因。iPhone 真机离线重载仍需补测。
